# Security reporting

Report suspected vulnerabilities privately to [apps@ydesignz.co.za](mailto:apps@ydesignz.co.za). Ydesignz is the project steward; the project homepage is [ydesignz.co.za](https://ydesignz.co.za). The steward supplied this contact; mailbox delivery and monitoring have not been independently tested, and no response-time commitment is promised.

Include the affected package/version, a minimal fictional-data reproduction, expected and observed behaviour, and the potential impact. Do not send credentials or real memorial data. Agree a disclosure plan privately before publishing exploit details. Do not put vulnerabilities, personal information or credentials into public issues.

The suite is an unpublished development version; no released-version support window is promised. Review [the security model](docs/SECURITY_MODEL.md) for the trust boundary, redirect limitations, host-header ownership and logging risks. Dependency advisory results are a dated check, not a security guarantee. Any eventual security fix must include regression coverage, affected-version guidance and a private disclosure plan agreed with the reporter.
